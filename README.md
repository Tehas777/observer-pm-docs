# 📊 Project Management Documentation: Observer

> **Project Name:** Observer  
> **Product Type:** Online Media / Analytical Journal on WordPress  
> **Role:** Project Manager  
> **Target Period:** November 2026 (Sprint 1)  

---

## 1. Project Overview & Vision

**Observer** — це аналітичний журнал на базі WordPress, який трансформує сухі державні відкриті дані (`statgo.ua`) у зрозумілі, якісні та корисні для суспільства цифрові статті й дослідження.

* **Головна мета на найближчі 3 місяці:** Перетворити Observer на стабільно працюючий аналітичний ресурс із регулярним потоком якісних публікацій, прозорими процесами та базовою вимірюваною аудиторією.
* **Підхід:** «Бізнес над технологіями» — фокус на цінності контенту для читача та самоорганізації команди.

---

## 2. Роль PM, зона відповідальності та повноваження

* **Зона відповідальності:**
  * Управління життєвим циклом задачі (від сирого дата-дослідження до релізу на сайті).
  * Побудова та ведення беклогу, пріоритизація завдань (MoSCoW).
  * Контроль дедлайнів, фасилітація процесів та управління ризиками.
  * Синхронізація команди та комунікація із замовником (Product Owner).
* **Повноваження:** Ухвалення рішень щодо черговості робіт, вибору інструментів та формату командної взаємодії. Вплив базується на прозорості процесів і якісній комунікації.

---

## 3. Комунікація із замовником і командою

* **З із замовником (Product Owner — Михайло Максимов):**
  * Асинхронний звіт наприкінці тижня (досягнення, блокери, плани). Принцип: *«Приносити готові варіанти вирішення проблем»*.
* **З командою (аналітики, дизайнери, розробники):**
  * **Понеділок:** Старт спринту, планування задач.
  * **Середина тижня:** Оперативний чекап у чаті, контроль блокерів.
  * **Кінець тижня:** Демо результатів та ретроспектива.
  * **Канали:** Telegram-чат + Trello / Notion / GitHub Projects для трекінгу.

---

## 4. Цілі, пріоритети та критерії успіху

* **Розподіл фокусу (Пріоритети):**
  1. **Контентний флоу (50%):** Шлях від аналітика до опублікованого матеріалу.
  2. **UX та структура сайту (30%):** Покращення навігації, категорій та пошуку на WordPress.
  3. **Аналітика та просування (20%):** Підключення GA4/GSC, соціальне поширення.
* **Критерії успіху (KPIs):** Регулярність виходу матеріалів, наявність якісної PM-документації, самостійність команди.

---

## 5. Організація процесів та інструменти

* **Методологія:** Гібрид Scrum та Kanban (тижневі спринти + дошка завдань).
* **Інструменти:** 
  * Управління задачами: Trello / Notion / GitHub Projects.
  * Платформа: WordPress (адмін-панель).
  * Аналітика: Google Analytics (GA4) / Search Console.

## 6. Початковий беклог та User Stories (MoSCoW)

### Epic 1: Управління контентом (Content Flow)
* **US-1.1: Шаблон структури статті**
  * *As a* редактор/аналітик, *I want to* мати стандартний шаблон оформлення досліджень, *So that* усі матеріали мали єдиний професійний стиль.
  * *AC:* Затверджено структуру (Заголовок, Лід, Інсайти, Візуалізація, Методологія) у WordPress.
* **US-1.2: Регламент публікації**
  * *As a* PM, *I want to* мати чіткий статусний ланцюжок (*Чернетка -> На перевірці -> Опубліковано*), *So that* бачити реальний стан готовності матеріалів.

### Epic 2: Користувацький досвід (UX/UI & Navigation)
* **US-2.1: Категоризація та фільтрація**
  * *As a* читач, *I want to* фільтрувати статті за темами (Економіка, Бюджет тощо), *So that* швидко знаходити потрібну аналітику.
* **US-2.2: Мобільна адаптивність**
  * *As a* мобільний користувач, *I want to* комфортно читати статті та розглядати графіки на смартфоні.

### Epic 3: Аналітика (Analytics)
* **US-3.1: Підключення веб-аналітики**
  * *As a* PM, *I want to* бачити статистику відвідуваності та джерела трафіку, *So that* приймати рішення на основі даних.

---

## 7. Ризики та відкриті питання

* **Ризики:** Нерегулярність постачання матеріалів від аналітиків, відсутність зафіксованих розробників у штаті.
* **Відкриті питання до замовника:**
  1. Чи є вже налаштована аналітика на сайті, чи це робимо з нуля?
  2. Чи планується виділений розробник для правок у WordPress, чи робимо зміни силами платформи/плагінів?
